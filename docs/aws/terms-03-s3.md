## S3（Simple Storage Service）

> [!NOTE]
> ファイルを容量無制限に置けるAWSの倉庫サービス

読み方は「エススリー」です。  
本業はストレージで、画像・動画・ログ・バックアップの置き場として現場でも定番です。  
静的サイトの公開も可能です。  
→倉庫を「Webサーバー風に」使う応用機能です。

| 使われ方               | 例                                       | ハンズオンでの登場 |
| ---------------------- | ---------------------------------------- | ------------------ |
| ファイル置き場（本業） | 画像・動画・ログ・バックアップ           | 使用しない         |
| 静的サイト公開         | HTML/CSS/JSの配信                        | 3章・4章で使用     |
| 他サービスの土台       | Lambdaの入出力、データ分析の元データとか | 使用しない         |

**つまずきポイント**

- バケットは東京リージョンに作られているか確認しましょう。
  - リージョンの考え方は[terms-02の用語集](terms-02-account.md#リージョンとグローバルサービス)を参照。

**公式ドキュメント**: [Amazon S3 とは](https://docs.aws.amazon.com/ja_jp/AmazonS3/latest/userguide/Welcome.html)

## バケットとオブジェクト

> [!NOTE]
> バケットは「入れ物」、オブジェクトは「入れたファイル1つ1つ」

S3ではまずバケット（バケツ）を作り、その中にファイルをアップロードします。  
アップロードされたファイル1つ1つをオブジェクトと呼びます。

`TIPS:` バケツに例える

- バケット＝バケツ本体
- オブジェクト＝バケツに入れたモノ
- バケットポリシー＝バケツに貼った「触っていい人リスト」

**バケット名前空間**

手順書では `アカウントのリージョナル名前空間（推奨）` を選びます。  
この設定なら、自分のアカウント内で好きな名前を付けられます。  
→私も皆も「penguin-kawaii」バケットが作れます。  
※以前は全世界のAWSアカウントでバケット名が一意である必要がありました。  
→私が「penguin-kawaii」バケットを作りたくても、世界中の誰かが同じ名前をつけていたら作れませんでした。

**つまずきポイント**

- バケット名は後から変更できません。
  - 変えたくなったら作り直しになります。
- バケット内の「フォルダ」は見た目だけで、実体はファイル名の一部です。
  - `assets/icon.svg` という名前のオブジェクト、が正体です。

**公式ドキュメント**: [バケットの概要](https://docs.aws.amazon.com/ja_jp/AmazonS3/latest/userguide/UsingBucket.html)

## 静的ウェブサイトホスティングとウェブサイトエンドポイント

> [!NOTE]
> バケットを「簡易Webサーバー」に変えるスイッチと、その公開URL

有効化すると、バケットにウェブサイトエンドポイント（公開URL）が生えます。

```text
http://<バケット名>.s3-website-ap-northeast-1.amazonaws.com
```

**インデックスドキュメント**

URLの末尾が `/` のとき、代わりに返すファイルの指定です。  
`index.html` を指定するので、トップURLを開くだけでサイトが表示されます。

**HTTPSに対応しない？**

このエンドポイント、httpしか使えません。  
→本番で使うにはつらいので、4章でCloudFrontを挟んでHTTPS化します。

**公式ドキュメント**: [ウェブサイトエンドポイント](https://docs.aws.amazon.com/ja_jp/AmazonS3/latest/userguide/WebsiteEndpoints.html)

## ブロックパブリックアクセス

> [!NOTE]
> バケットを公開させないための安全ロック。デフォルトは全ロック

S3は「設定ミスで社内ファイルが全世界に公開されていた」という事故が定番のサービスです。  
そのため、公開につながる設定を一括で無効化するロックが標準装備されています。

なぜ外すのに確認チェックまで求められる？  
→それだけ事故が多かったからです。  
→静的サイト公開はS3では例外的な使い方、と覚えておきましょう。

**つまずきポイント**

- 外すのは「このバケットを全世界に公開してよい」ときだけです。
  - 今回は公開が目的なので外しますが、仕事のバケットでは基本触りません。
- 4章でCloudFront構成に変える際、このロックを有効に戻します。
  - 公開を閉じてもCloudFront経由なら配信できる、が4章のポイントです。

**公式ドキュメント**: [S3のブロックパブリックアクセス](https://docs.aws.amazon.com/ja_jp/AmazonS3/latest/userguide/access-control-block-public-access.html)

## バケットポリシーとARN

> [!NOTE]
> バケットポリシーは「このバケットの触り方ルール」をJSONで書いたもの。ARNはAWSリソースの住所

手順10でペーストするJSONの中身です。  
1行ずつ意味が分かると、ただのコピペが「読める設定」に変わります。

| 項目      | 今回の値            | 意味                                |
| --------- | ------------------- | ----------------------------------- |
| Sid       | PublicReadGetObject | ルールの名前（自由につけてよい）    |
| Effect    | Allow               | 許可する（Denyなら拒否）            |
| Principal | `*`                 | 誰に → 全員（未ログインの人も含む） |
| Action    | s3:GetObject        | 何を → オブジェクトの読み取りだけ   |
| Resource  | `<バケットARN>/*`   | どこを → バケット内の全オブジェクト |

つまりこのポリシーは「全員に、読み取りだけ、全ファイルを許可」です。  
書き込みや削除は許可していないので、サイトを見られても改ざんはされません。

**ARN（Amazon Resource Name）**

AWS内のリソースを一意に指す住所です。

```text
arn:aws:s3:::<バケット名>
```

`TIPS:` バケットARNはどこで見る？

- ポリシー編集画面の上部に「バケットARN」がコピーボタン付きで表示されています。

**つまずきポイント**

- `Resource` の末尾の `/*` を忘れるとエラーになります。
  - `/*` なしはバケット自体、`/*` ありは中のオブジェクト、を指すためです。

**公式ドキュメント**: [バケットポリシーの使用](https://docs.aws.amazon.com/ja_jp/AmazonS3/latest/userguide/bucket-policies.html)
